# 两端性能优化验收（2026-09-28）

本轮代码基线为 `45e0196`（应用代码与 Orin 已安装的 `3c95a9a` 相同），优化提交 `c84e5ca`、`60daa51`，开发分支 dev。测试顺序为 Orin 实际样本、本机硬件实际样本、完整同规格长片重试。原录像、JSONL、头像清单与 Scene 文件保留；自动长片烧录保持关闭。

## 保留的优化

Scene JSONL 布局缓存每 512 个对象建立一个字节范围索引，记录整个块的最早开始与最晚结束；不假定对象按时间排序。剪辑只解析与范围相交的块，保持跨范围对象、对象顺序、中文及 Unicode 内容。索引必须匹配文件的设备、inode、大小、修改时间并连续覆盖文件；旧缓存或无效索引回退完整读取。缓存仍限制两个、合计 512 MiB，索引一起计入并清理。

跨卷成片复制、SHA-256 计算及读回验证的缓冲从 64 KiB 调到 1 MiB。复制取消检查、校验失败保留源成片、旧目标回滚及原子替换均保留。相同磁盘内的 rename 不受影响。

没有根据旧样式的 CUDA 视觉报告启用现代样式的另一种 CUDA 滤镜拓扑，也没有取消存储完整性检查。索引和跨卷缓冲主要改善准备及发布阶段，不能声称索引让正式 GPU 渲染快 100 倍。

第三项优化用于 Jetson 原生 Scene：CUDA helper 已经写出带时间戳、通过 PTS bridge 和存储校验的 MKV 后，直接作为后续音频封装的视频输入。原链路还会将这份全长视频再次无重编码复制到另一个 MKV；对本片约 17.1 GB 的视频，这产生额外共享盘读写和临时空间占用。新链路保留原生视频及最终 MP4 的独立时间轴和画面门禁。阶段进度按渲染、封装分别计时，封装从 0 开始的媒体时钟不再覆盖渲染进度或显示虚假的渲染 fps。

## 真实导出

Orin 使用正式服务用户、正式 FFmpeg 和未修改的已验收 CUDA helper，在隔离工作区导出原录像，原始源文件指纹不变。

| Orin 样本 | 总耗时 | 正式渲染链路 fps | 成片弹幕匹配 |
| --- | ---: | ---: | ---: |
| 0～30 秒，h5-card | 54.926 秒 | 169.46 | 99.86% |
| 60～90 秒，h5-card | 47.300 秒 | 157.56 | 99.88% |
| 0～300 秒，h5-card | 160.283 秒 | 183.94 | 99.86% |

流水线 NVDEC → CUDA Scene NVMM → H.265 NVENC；三个样本 PTS bridge 均通过，三层时间映射最大误差为 0。5 分钟输出 18000 帧，媒体时长 300.0017 秒。总耗时含准备、真实源预检、画面验收及发布，不等于渲染阶段耗时。

新原生视频复用路径在 Orin 又完成 0～30 秒、60～90 秒、0～300 秒三个真实 GPU 样本；均记录了“复用已通过 PTS 与存储校验的原生 MKV”，PTS bridge 及画面门禁通过，弹幕匹配率在 99.86%～99.88% 之间。5 分钟总耗时 190.866 秒，测试期间共享盘同时进行全长成片写入，因此不能用它与上表单独运行的 160.283 秒对比推断性能回退或增益。

同一份 9 月 12 日录像先完整跑通一次 GPU 重绘，耗时 4662.353 秒（约 77 分 42 秒），原生编码 549333 帧、173.30 fps。五处跨全片抽样弹幕画面匹配率分别为 99.86%、99.91%、99.86%、99.64%、99.60%；PTS bridge 通过。纹理缓存峰值约 344.5 MiB，低于 512 MiB 上限。Node RSS 间隔采样峰值约 2004 MiB，不能代表包含 helper 的整机峰值；Orin 使用统一内存，不能据此报告独立显存峰值。

为验收新封装路径，将**上述同一份已经真实 GPU 渲染并独立探测过时间轴的原生 MKV**用于全长重试的后处理，重新执行 10 秒真实 GPU 预检、最终音频封装、全片帧校验和五处画面抽检，没有再次重绘两小时视频。该后处理及验收耗时 1193.443 秒，不能称为第二次完整 GPU 烧录耗时。最终 MP4 为 17,332,755,625 字节，视频时长 9172.622625 秒、音频时长 9172.626458 秒，实测终点差约 0.00383 秒，时间轴可安全复制；五处画面匹配率仍为 99.86%、99.91%、99.86%、99.64%、99.60%。原合并录像、弹幕 JSONL、Scene 缓存及之前的正式输出均保留；隔离测试输出在证据归档后清理。
