## 原因与保留的修复

此前一段规格变化就让整组录像重编码，健康的约 3 小时 13 分钟 4K 长段也受影响。界面显示 NVDEC，但合并没有传入原生解码所需配置，实际由 FFmpeg CPU 解码、CPU 放大到 4K、输出大体积 I420，经 GStreamer 硬件编码，约 16–17 fps。

- 严格检查规格、AAC 48 kHz 双声道、已知时间轴及音画首尾偏移后，健康匹配段只重封装为 Matroska，不重新编码。统一容器时间基并保留时间戳；与重编码段交界处额外检查解码连续性，最终仍检查原成片时间轴。
- Jetson 规范化保持 FFmpeg 解码与时间轴修复，向 GStreamer 传递源尺寸 I420，在 NVMM 中缩放后硬编。同长宽比、8 位 SDR 才准入，其他布局保留兼容路径；Windows 仍沿用其自身解码与编码后端。
- 修正实际解码显示。规范化 ETA 排除之后可无损复用的媒体时长。
- 自动合并的取消进度也持久化并在重启后恢复；重试 API 可指定 `mergeGroup`，只解除明确场次的取消状态。解决取消后重启再试时找不到任务的问题，不恢复其他已取消场次。
- 延续空间修复：本机不足时独立共享盘工作目录、验证后发布、失败保留源文件，确定性空间不足不再三次重跑。
