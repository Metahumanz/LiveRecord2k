# Orin 烧录尾部截断与预检定位死锁修复验收

2026-10-01 至 10-02，在 AGX Orin 的正式 `bili-record-2k` 服务执行，安装版本仍显示 0.9.2。本次覆盖服务 bundle 与 GPU helper，保留覆盖前备份；未发布新版本。

## 原因与修复

用户失败任务为 `7953876_宴宁ccccc_20261001_212131.clean.mp4` 的 0–2332.5 秒烧录。源音频比视频提前结束，原封装的 `-shortest` 随源音频 EOF 截掉已渲染的视频尾帧，最终视频仅 2332.240 秒。有限时长 AAC 封装增加 `apad` 后按时间戳 `atrim`，让视频 EOF 决定有效尾部；有限时长音频复制路径也不再随短音频截断视频。时间轴验收标准保持不变。

实测还暴露非零分段定位的启动竞争：预热阶段 BLOCK 住 NVDEC 输出后，解码捕获缓冲耗尽，demux 在等待解码器时占住 FLUSH seek 所需锁。Python 栈停在 `seek()`，GDB 栈证实 demux/解码器相互等待。改为在 PTS 计数探针之前丢弃预热帧、持续排空解码器；新的定位 SEGMENT 到达即放行首帧，避免等待同步 seek 返回而丢掉有效帧。预检失败诊断同时保留退出码、信号和超时标记，避免把正常 Argus 提示当成根因。

本地提交：`790497a`（封装）、`ab4a842`（定位）、`fe8eafa`（诊断）。
