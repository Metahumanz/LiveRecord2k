# 大航海重复、醒目留言换行与 emoji 烧录验收

## 原因与修复

Orin 的真实 JSONL 中，`GUARD_BUY` 后 33–134 ms 会出现一条 `USER_TOAST_MSG_V2`，其 UID、用户名、等级和价格均为空。旧版把空通知默认成“大航海”，显示为第二张“观众”卡片。现在入口拒绝空通知，读取历史 JSONL/事件缓存时也过滤这一明确无效的记录；正常购买及真正名为“观众”的用户继续保留。补充嵌套身份字段，避免丢失已有的 UID、名字和头像 URL。

四种样式的醒目留言按实际正文宽度换行，卡片高度随正文增长；保留原有配色、头像和价格样式。换行、截断和宽度计算使用字素簇，避免拆开国旗、肤色、家庭组合表情。正文行数上限为 64。

Unicode emoji 使用随安装包分发的离线 Twemoji 图片。新录制解析 B 站整条图片弹幕及混合文字中的 `extra.emots`，保留原文和图片元数据，将图片放入录像现有图片快照清单。合并、清理和离线导出复用同一套生命周期，下载并发、图片大小和队列继续受限；表情不依赖开启观众头像。

Scene Graph 新增 `Image` 原语，Web 预览、FFmpeg/ASS 兼容烧录和 Jetson CUDA 都支持。长桌面任务包含图片时使用受对象数和时长限制的分段路径；纯表情弹幕也参加画面验收。包含 emoji 的礼物文本保留聚合数量变化。图片缓存按系统账号隔离，正式服务与验收账号不会争用私有缓存目录。
