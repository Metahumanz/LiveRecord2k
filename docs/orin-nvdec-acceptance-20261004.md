# Orin 原生 NVDEC 停滞修复与验收

基于 dev 的 `d1dc96d`。问题场次 `883263_真栗_20261003_200838`，21 段，约 3 小时 49 分钟。安装版本仍为 0.9.3，本修复尚未发版。

## 四秒停滞的证据与修复

1080p `201740.clean.mp4` 在不含 Scene、缩放或编码的 `qtdemux → h264parse → nvv4l2decoder → fakesink` 管线也停滞：解码约 250 帧，媒体 4.183 秒。改成本机 MP4、Annex B、排空音频、增加解码缓冲、enable-full-frame 或 disable-dpb 均不能解决。调试器显示厂商 V4L2 输入/输出等待以及 libnvparser/libnvmmlite_video 等待，未定位到 NVIDIA 驱动内部的具体算法缺陷。

同一 SPS ID 的色彩信令在未标记与 BT.709 之间切换。只统一 timing、SAR 或 video_format 无效，统一色彩字段后可以继续解码。源中还有畸形 filler NAL：直接使用 h264_metadata 时，FFmpeg 即使退出码为 0，也会报 BSF 错误并丢失 4 个图片包。因此必须先 `filter_units=remove_types=12`，再统一 SPS 色彩字段，不修改 VCL 图片或 timing。

实际 12 秒样本前后均为 721 帧，逐帧像素 MD5 与微秒级时间戳完全相同；所有帧记录的 SHA-256 为 `a5a5592bc4f08e2000c8ad05bfdbd76486720d44c3411346ee3dcafc937cba85`。没有对兼容输入重新编码。已标记的受支持 SDR 色彩及全范围标记保留；未知 HD SDR 按现有 BT.709 管线约定处理，HDR、10 位和无法确定的色彩不进入此改写。

## 执行路径与附带问题

- 规范化：按段准备无损 H.264 兼容输入，真实源预检后使用 NVDEC → NVMM/VIC 缩放 → NVENC → 顺序 MKV → 原音频规范化封装。HEVC 使用 h265parse，不进入 H.264 BSF。媒体探测的带括号编码说明不能直接作为 parser 的编码 ID。
- 健康匹配的长段继续只重封装，不重新解码或编码。
- 无 Scene 对象的纯合并跳过 nvivafilter/CUDA 绘制，仍保持解码→输出逐帧 PTS 审计。
- 请求、兼容 MP4、预检与运行时 TMPDIR 使用本机短路径；大型顺序 MKV 可使用共享盘。仅保留一个源段的兼容输入，并在结束/失败/取消时清理。
- 小样还暴露了退出竞争：输出和 PTS 验证已完成，Python 退出卸载 libnvbufsurftransform/libnvvic 时，black-lead 的 VIC 工作线程仍执行库内代码，导致 SIGSEGV。等待 NULL 状态、释放回调引用并在解释器退出前执行 Gst.deinit 后，同一深路径 GDB 对照正常退出。深路径是复现条件之一，不能据此断言路径长度本身是驱动根因。
- 常规预检覆盖 30 秒，明显稀疏的源扩大到最多 120 秒并受源长度限制，避免样本终点落在源文件的 PTS 空洞内。保留源缺帧时间轴；不能恢复源中不存在的画面。
- 预检 30 秒无输出即停止；正式准入后失败返回实际原因，不整段 CPU 重跑，也不触发整组编码器重试。未获准的源明确记录兼容路径原因和实际解码器。
- 合并界面报告真实 NVDEC、NVMM 与编码器及原生 fps。

## 长片封装收尾修复

首次全硬解合并在最终 MP4 的 faststart 第二遍索引搬移阶段，媒体时间戳不再推进，被 120 秒无媒体进度看门狗误杀。随后 SIGKILL 被误报为疑似内存不足；此次已有明确的应用超时终止证据。失败后工作区按旧逻辑清理，源 21 段保留。

合并 MP4 按时长、帧率及 AAC 包数保守预留前置索引空间（最多 512 MiB），通过 `-moov_size` 消除搬移整片媒体数据的第二遍写入。无法合理估计时保留 faststart，识别其明确的第二遍日志，采用单独的有限收尾超时，显示真实索引阶段；用户取消仍有效。应用看门狗和主动取消不再算作 OOM，也不再因收尾超时触发整组转码。无损复用清空上一段的解码与渲染性能，避免误导显示。

真实最长源 `230242.clean.mp4`，4064 秒、5,197,490,171 字节：共享盘前置索引封装 91.014 秒，输出 5,225,917,143 字节；预留 36 MiB，实际 moov 9,321,740 字节，moov 位于 mdat 之前。前后视频 243720 帧、音频 190406 包一致，视频时长差 0.625 ms、音频时长差 17 ms，源文件未修改。测试专属目录已清理。三段真实源合并仍通过，音画差 12.208 ms。本机 quick/integration 均通过，增加跨日志块的 faststart 识别、收尾超时及误 OOM 分类回归。
