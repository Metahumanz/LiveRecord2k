# Orin 原生烧录画面验收误报修复

## 原因与改动

10 月 3 日真栗合并录像的烧录在十秒预检阶段失败，报告文字边缘匹配率 31.4%。原生输出抽帧实际包含弹幕；错误来自默认滚动样式的 CPU 参考画面与 NVMM 输出未使用相同的时钟及像素坐标。

真实 3840×2160 H.264 源文件首个视频 PTS 为 0.021 秒，音频为 0。NVMM 按源 PTS 绘制，参考滤镜的 `setpts=PTS-STARTPTS` 却丢失了这 21 毫秒。4K 滚动弹幕因此偏移约 8–12 像素；此外 FFmpeg overlay 默认截断坐标，原生渲染按最近像素放置，产生额外一像素偏差。

原生路径的预检与最终抽帧参考现在保留输入时钟，并按最近像素放置图层。桌面普通路径继续使用原时钟设置，ASS 兼容拓扑保持原行为。没有修改像素验收算法、55% 门槛或 CUDA helper，也没有通过平移匹配或降低标准放行。

这份源文件存在真实的 PTS 间断，十秒内并非完整 600 帧；修复保留源时间轴，未把名义 60 fps 当成必须补齐的帧数。

## 实机验证

- 同一长片范围 0–13745.89 秒重新构建：原始事件 15653，范围内 15634，Scene 对象 25744，与失败任务一致。生产十秒预检通过：匹配率 **65.117%**，预期边缘 22203 像素、匹配 14458；source→Scene→编码的 PTS 偏差均为 0。短预检吞吐 92.4 fps。
- 正式 WebUI 队列导出同一源的前五分钟，使用默认滚动样式、顶部四分之一区域、弹幕与礼物、Jetson H.265、CRF 24。原生预检、封装、音视频时间轴以及最终弹幕抽帧均通过，并记录成功导出。五分钟范围触发一个最终画面样本；更长任务才使用分布式抽帧。运行中实际链路为 NVDEC → NVMM/CUDA Scene → NVENC，观测吞吐约 108 fps；这是运行中的快照，非全任务平均值。
- 成片为 3840×2160 HEVC + AAC，494693449 字节。视频流起点 0.021 秒、时长 300.014 秒；音频起点 0、时长 300.021333 秒。2.01 秒与 250 秒抽帧目视确认中文弹幕存在。
- 新增实际 FFmpeg 媒体回归：构造 21 ms 视频前导，独立绘制原生时钟的移动文字，验证旧参考失败、新参考通过、完全没有文字的输出仍失败。本机及 Orin 内置完整 FFmpeg 均通过。quick、integration 全组通过；夹具随后改用两端均支持的 FFV1/NUT，单独在两端再次通过。
