# Orin 长片导出、性能与手动合并检修（2026-09-28）

## 故障证据与处理

原长片在渲染完成后的时间轴校验阶段失败：临时 MKV 出现连续非法 EBML 数据，最终报扫描超时。同期内核有 CIFS SMB 签名校验错误。这说明必须检查媒体和存储完整性；现有证据不能证明共享盘异常是唯一原因。原录像、JSONL 与 Scene 缓存均保留，没有关闭 SMB 签名或改动系统挂载。

Jetson 原生 MKV 改为顺序封装；记录发送到文件 sink 的字节数和 SHA256，关闭管线、同步文件并释放读缓存后读回验证。跨卷发布同样核对复制字节和 SHA256。媒体校验通过单次流式 packet/CRC 扫描同时取得视频、音频时长与告警，按文件大小设置期限，发现非法 EBML、损坏包或 I/O 错误立即停止。同一文件指纹下复用扫描结果，文件变化失效；扫描缓存仍正确释放子进程跟踪引用。

重复媒体告警按类别汇总，保留首次原因、周期次数和结束总数；不同错误保留。字体回退汇总不会重复发送未变化的计数。没有把真实损坏当作可以忽略的日志。

5 分钟设备测试发现，原生管线在安装帧探针前进入 PLAYING，会漏掉启动预取帧并导致 PTS bridge 验收失败。探针现在先于启动安装；非零剪辑起点在解码器输出处阻塞并完成 seek 后再放行。仍保留逐帧 PTS 验收与晚期失败停止策略。

## 性能与交互

- CUDA 纹理直接生成 RGBA，复用相同像素身份，保留文字小数坐标相位与头像文件指纹。纹理按需上传，GPU 纹理缓存限制 512 MiB；空白帧跳过合成，绘制栅格限制在可见区域。资源或 EGL/CUDA 失败明确停止，不能静默丢弹幕。
- 大量事件的 Scene 布局在受限后台进程构建；主进程只接收选中范围内对象及实际使用资产。布局缓存最多两个、合计 512 MiB，进程退出清理。纹理工作空间动态估计并保留安全余量。
- 头像按实际来源去重，受限并发复制，等所有已启动复制结束才报告失败。恢复使用有效 JSONL 时不额外读取完整 Scene 事件缓存。
- 手动合并提供默认不勾选的“合并完成后删除源文件”。成片、元数据、JSONL、头像及 Scene 保存和验收通过后才清理。源录像与配套文件指纹变化、占用、取消或配套保存失败时保留源文件。所有检查完成后才进入清理提交阶段；该阶段禁止新导出占用这些源文件，并隐藏取消按钮。
- “设为默认”悬停说明保存导出类型、烧录内容、显示区域、样式与头像模式；新增持久化的纯净/烧录默认导出类型。不会保存源文件、剪辑起止或本次输出目录。沿用既有 CSS、配色和布局。
