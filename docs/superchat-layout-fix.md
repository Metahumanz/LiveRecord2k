# SC 烧录布局修复（2026-10-07）

SC 标题、头像、昵称、金额和多行正文应有明确的区域。原始 Scene 样式将头像按整张卡片居中，正文较长时头像会进入正文区；昵称使用正文白色，落在浅色标题栏上对比不足。侧栏样式把金额宽度和昵称预算分开估算，窄卡片会出现遮挡，极简样式还把昵称限到文字区的 35%。

修复原始样式头像的标题区定位、昵称颜色和金额信息。三套侧栏样式沿用既有配色及卡片外观，SC 正文移到标题区下方，昵称和金额使用同一组布局尺寸；窄卡片改为上下排列金额。CPU ASS 与 CUDA Scene 共享这些尺寸。其他互动卡片沿用原来的布局。

新增 `scripts/superchat-layout.test.cjs`，覆盖四套样式、横屏/竖屏/4K、220/375 基准卡宽、位图头像、长昵称和完整多行正文。完整快速回归通过。

`scripts/superchat-render-acceptance.cjs` 在 Orin 对已有 720×1280、5fps 视频的 4 秒范围实测 NVDEC → NVMM/CUDA Scene → NVENC。使用测试头像和人工 SC，未改动已有成片；原录像与 JSONL 当前不在挂载目录，不能声称重烧了用户原来的 SC。四套样式的昵称和正文分别验收通过。h5-card 和 bubble 昵称像素匹配 100%，正文约 94.6%/94.7%；minimal 正文约 87.9%。原始样式粗体昵称在 Pillow 与 drawtext 之间存在 1 像素字形基线差异，此设备测试单独记录该偏移（校准后约 98.6%），正文约 72.4%。正式输出的像素验收逻辑和阈值未修改，并验证缺失文字不能通过验收。

六组 ASS/CUDA 视觉一致性测试（含 0/1.019s 前导）全部通过，报告升级为 `ass-compat-v5`，旧报告无法获得新布局的生产准入。Orin 已部署后端并安装真实测试生成的 v5 报告，保留覆盖前后端与报告备份。

验收证据：`docs/evidence/orin-sc-layout-20261007/report.json` 与 `conformance.json`。修改只影响新烧录；已有成片中的错误像素需要用原录像、JSONL 重新生成。

## 字体与居中复验

用户指出昵称仍然靠上、CNY 标签文字没有居中、正文过小过细。侧栏 SC 的昵称改为与头像共用垂直中心锚点（ASS `an4`）；金额改为标签中心锚点（`an5`），CUDA libass 纹理和网页预览同步处理。每段 ASS 只写一个对齐标签，避免 libass 保留首次对齐而忽略后加的标签。昵称中的 emoji 保留同一垂直中心。

h5-card/bubble 的 SC 字号由原来的配置字号 × 0.86 改为 × 1.08；正文采用与昵称相同的字号和 700 粗体，原来正文只有昵称的约 0.66 倍。minimal 的 SC 字号由 × 0.62 改为 × 0.86，正文也使用粗体。原始样式的 SC 正文和金额加粗。SC 卡片高度向上取整，避免排队重排时小数高度积累造成 ASS/CUDA 边界偏移；其他互动卡片的字号与布局保留。

最终 Orin 实测四套样式的昵称、正文、金额分别通过抽帧检查，PTS bridge 全部通过。实际 libass 字形边界检查：昵称垂直中心偏差 0.5px，金额水平中心偏差 0–0.4px、垂直中心偏差 0.5px。原始样式的粗体昵称、正文继续记录 Pillow/drawtext 的 1px 基线差异，设备样本校准后的匹配率约 99.3%/81.4%；正式输出的验收阈值未改动。

六组严格 ASS/CUDA 一致性复验全部通过（最大 RGB 均差 1.369，最大变化像素比例 1.92%，阈值仍为 2 / 2%）。报告升为 `ass-compat-v6`，拒绝旧 v5 报告。Orin 已同时覆盖后端、GPU helper、网页预览和真实 v6 验收报告，覆盖前文件以 `.before-sc-typography-20261007` 保存备份。

证据：`docs/evidence/orin-sc-typography-20261007/` 的 `report.json`、`conformance.json`、`alignment.json` 及实际烧录局部截图。测试源仍为已有成片，SC 和头像为测试数据。
