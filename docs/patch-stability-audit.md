# 最近补丁稳定性审计

检查范围为低帧率/空编辑区间修复、FFmpeg 三段链退出处理、emoji 与多行布局、原生画面验收，以及导出默认值保存。没有把短样本通过扩大为所有设备、所有录像均已验收。

## 本轮发现并修复

1. **未选择录像时，后台状态推送重置导出草稿。** 已用实际 App 处理器复现：修改为烧录、极简样式后收到普通状态推送，旧代码变回纯净片段。现在默认值只在首次初始化和主动选择录像时应用；没有源文件时调整的导出类型、布局及显示区域不再被推送重置。
2. **初始 GET 与 SSE 到达顺序影响默认值和增量状态缓存。** SSE 已初始化页面后，迟到的初始 GET 可能回退页面与 recorder 缓存，下一条日志增量又将旧设置推回页面。现在页面及 recorder 的初始加载都保留已收到的更新状态。补充实际客户端 HTTP/SSE 乱序及后续日志增量回归。
3. **同进程清理临时图片后，emoji 内存缓存返回失效路径。** 已复现 ENOENT。现在使用缓存前检查文件是否仍存在，缺失时从离线资源重新原子生成。没有增加网络下载，也没有改变 CUDA 每帧绘制。
4. **验收期间取消仍可能保留诊断目录。** 最终验收将被中断的 FFmpeg 错误识别为取消；顶层导出在取消状态下不保留失败诊断，继续执行正常临时文件清理。真正画面失败仍保留诊断。
